Next we generate an independent production secret set. We will validate it locally but never start it against the existing local database—the encryption and JWT keys belong to a different deployment.

## 1. Create production configuration from the official template

From `deploy/self-hosted`:

```zsh
cp .env.example .env.production
chmod 600 .env.production
```

Your committed `.env.production.example` should remain a placeholder template, while `.env.production` will contain real secrets and stay ignored.

## 2. Generate secrets in an isolated temporary copy

The official generators modify `.env` directly, so don’t run them against your working local environment.

```zsh
SELF_HOSTED_DIR="$PWD"
PRODUCTION_PREP_DIR="$(mktemp -d)"

mkdir -p "$PRODUCTION_PREP_DIR/self-hosted"
cp -R . "$PRODUCTION_PREP_DIR/self-hosted/"

cp \
  "$SELF_HOSTED_DIR/.env.production" \
  "$PRODUCTION_PREP_DIR/self-hosted/.env"
```

Generate the legacy secrets, database password, dashboard password, and related encryption keys:

```zsh
cd "$PRODUCTION_PREP_DIR/self-hosted"

sh utils/generate-keys.sh --update-env >/dev/null
```

Generate the asymmetric ES256 signing keys and new `sb_` API keys:

```zsh
sh utils/add-new-auth-keys.sh --update-env >/dev/null
```

Copy only the generated environment file back:

```zsh
cp \
  "$PRODUCTION_PREP_DIR/self-hosted/.env" \
  "$SELF_HOSTED_DIR/.env.production"

chmod 600 "$SELF_HOSTED_DIR/.env.production"

cd "$SELF_HOSTED_DIR"
```

Do not delete the temporary directory quite yet; first check whether the authentication utility changed other required configuration:

```zsh
diff -u \
  docker-compose.yml \
  "$PRODUCTION_PREP_DIR/self-hosted/docker-compose.yml" \
  || true
```

If there is no difference, everything required is already present in your Compose file. If there is a difference, keep the output—we’ll review it rather than blindly replacing the working file.

## 3. Configure future public URLs

Open:

```zsh
nvim .env.production
```

Use reserved placeholder domains for now:

```dotenv
SITE_URL=https://app.example.com
API_EXTERNAL_URL=https://api.example.com
SUPABASE_PUBLIC_URL=https://api.example.com

ADDITIONAL_REDIRECT_URLS=https://app.example.com/**

ENABLE_EMAIL_SIGNUP=true
ENABLE_EMAIL_AUTOCONFIRM=false
```

The important production change is:

```dotenv
ENABLE_EMAIL_AUTOCONFIRM=false
```

We will replace the placeholder domains after choosing the real domain and deployment topology.

Leave SMTP values as explicit placeholders:

```dotenv
SMTP_ADMIN_EMAIL=replace-before-deployment@example.com
SMTP_HOST=replace-before-deployment
SMTP_PORT=587
SMTP_USER=replace-before-deployment
SMTP_PASS=replace-before-deployment
SMTP_SENDER_NAME=Personal Supabase
```

## 4. Validate required secrets without printing them

```zsh
for variable in \
  POSTGRES_PASSWORD \
  JWT_SECRET \
  ANON_KEY \
  SERVICE_ROLE_KEY \
  SUPABASE_PUBLISHABLE_KEY \
  SUPABASE_SECRET_KEY \
  JWT_KEYS \
  JWT_JWKS \
  DASHBOARD_USERNAME \
  DASHBOARD_PASSWORD \
  SECRET_KEY_BASE \
  REALTIME_DB_ENC_KEY \
  VAULT_ENC_KEY \
  PG_META_CRYPTO_KEY
do
  value="$(
    sed -n "s/^${variable}=//p" .env.production
  )"

  if test -n "$value"; then
    printf 'OK: %s\n' "$variable"
  else
    printf 'MISSING: %s\n' "$variable"
  fi
done

unset value variable
```

Validate both JSON key structures:

```zsh
sed -n 's/^JWT_KEYS=//p' .env.production |
  jq -e . >/dev/null &&
  echo "JWT_KEYS is valid JSON"

sed -n 's/^JWT_JWKS=//p' .env.production |
  jq -e . >/dev/null &&
  echo "JWT_JWKS is valid JSON"
```

Check the new API-key formats without revealing them:

```zsh
grep -q '^SUPABASE_PUBLISHABLE_KEY=sb_publishable_' \
  .env.production &&
  echo "Publishable key format is valid"

grep -q '^SUPABASE_SECRET_KEY=sb_secret_' \
  .env.production &&
  echo "Secret key format is valid"
```

## 5. Validate Compose interpolation

Clear any old exported variables that could override the file:

```zsh
unset JWT_JWKS JWT_KEYS
```

Then validate:

```zsh
docker compose \
  --env-file .env.production \
  --file docker-compose.yml \
  config --quiet
```

This parses the complete production configuration but does not start containers.

## 6. Remove the temporary preparation directory

After reviewing the Compose diff:

```zsh
rm -rf "$PRODUCTION_PREP_DIR"
unset PRODUCTION_PREP_DIR SELF_HOSTED_DIR
```

This removes only the temporary directory created with `mktemp`; it does not touch the repository or Docker volumes.

At this point we will have a separate production cryptographic identity. Next we’ll build `docker-compose.production.yml` to provide Linux named volumes, restrict database ports to localhost, place Envoy behind a future reverse proxy, and add production restart behavior. Supabase’s current self-hosting guidance recommends separate generated secrets and an HTTPS reverse proxy in front of Envoy.
