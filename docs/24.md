Perfect. The Storage milestone is complete.

Your persistent state is:

```text
PostgreSQL:
supabase_supabase-db-data

Attachment bytes:
supabase_supabase-storage-data
```

Now we begin step 3: create a consistent backup. We’ll stop services briefly so PostgreSQL metadata and Storage files represent the same point in time.

## 1. Create a backup directory

From `deploy/self-hosted`:

```zsh
BACKUP_ID="$(date -u +%Y%m%dT%H%M%SZ)"
BACKUP_DIR="../../backups/$BACKUP_ID"

mkdir -p "$BACKUP_DIR"

printf 'Backup directory: %s\n' "$BACKUP_DIR"
```

Do not commit `backups/` to Git. Add this to the repository’s `.gitignore`:

```gitignore
backups/
```

## 2. Record deployment information

```zsh
docker compose config --images > "$BACKUP_DIR/images.txt"
docker compose ps > "$BACKUP_DIR/services.txt"

docker volume inspect \
  supabase_supabase-db-data \
  supabase_supabase-storage-data \
  > "$BACKUP_DIR/volumes.json"

supabase --version > "$BACKUP_DIR/supabase-cli-version.txt"
```

Back up the migrations and deployment configuration:

```zsh
tar -czf "$BACKUP_DIR/project-config.tar.gz" \
  ../../supabase/migrations \
  docker-compose.yml \
  docker-compose.colima.yml
```

Do not copy `.env` into this directory yet. Secrets require a separately encrypted backup.

## 3. Create the logical PostgreSQL backup

Extract values without sourcing `.env`:

```zsh
POOLER_TENANT_ID="$(
  sed -n 's/^POOLER_TENANT_ID=//p' .env
)"

POSTGRES_PASSWORD="$(
  sed -n 's/^POSTGRES_PASSWORD=//p' .env
)"

SELF_HOSTED_DB_URL="postgresql://postgres.${POOLER_TENANT_ID}:${POSTGRES_PASSWORD}@127.0.0.1:5432/postgres?sslmode=disable"
```

Check the supported CLI options:

```zsh
supabase db dump --help
```

Create the Supabase-aware backups:

```zsh
supabase db dump \
  --db-url "$SELF_HOSTED_DB_URL" \
  --file "$BACKUP_DIR/roles.sql" \
  --role-only

supabase db dump \
  --db-url "$SELF_HOSTED_DB_URL" \
  --file "$BACKUP_DIR/schema.sql"

supabase db dump \
  --db-url "$SELF_HOSTED_DB_URL" \
  --file "$BACKUP_DIR/data.sql" \
  --use-copy \
  --data-only
```

Also preserve CLI migration history explicitly:

```zsh
supabase db dump \
  --db-url "$SELF_HOSTED_DB_URL" \
  --file "$BACKUP_DIR/migration-schema.sql" \
  --schema supabase_migrations

supabase db dump \
  --db-url "$SELF_HOSTED_DB_URL" \
  --file "$BACKUP_DIR/migration-data.sql" \
  --schema supabase_migrations \
  --use-copy \
  --data-only
```

Supabase recommends its dump command instead of raw `pg_dump` because it applies Supabase-specific filtering and produces portable SQL files. [Official backup and restore guidance](https://supabase.com/docs/guides/self-hosting/restore-from-platform).

## 4. Stop the stack for the Storage snapshot

```zsh
docker compose stop
```

Create a compressed archive of the attachment bytes:

```zsh
docker run --rm \
  -v supabase_supabase-storage-data:/source:ro \
  -v "$(cd "$BACKUP_DIR" && pwd)":/backup \
  alpine:3.22 \
  tar -czf /backup/storage.tar.gz -C /source .
```

This does not modify or remove either volume.

Restart the deployment:

```zsh
docker compose start
docker compose ps
```

Wait until the important services are healthy.

## 5. Generate checksums and inspect the backup

```zsh
(
  cd "$BACKUP_DIR"
  shasum -a 256 \
    roles.sql \
    schema.sql \
    data.sql \
    migration-schema.sql \
    migration-data.sql \
    storage.tar.gz \
    project-config.tar.gz \
    > SHA256SUMS
)
```

Check the artifacts:

```zsh
ls -lh "$BACKUP_DIR"

(
  cd "$BACKUP_DIR"
  shasum -a 256 -c SHA256SUMS
)
```

Make sure the SQL files are nonempty:

```zsh
for file in \
  roles.sql \
  schema.sql \
  data.sql \
  migration-schema.sql \
  migration-data.sql
do
  test -s "$BACKUP_DIR/$file" &&
    printf 'OK: %s\n' "$file"
done
```

Finally, clear secrets from the shell:

```zsh
unset POSTGRES_PASSWORD
unset SELF_HOSTED_DB_URL
unset POOLER_TENANT_ID
```

Do not delete or replace any current volumes. Once this backup succeeds, we’ll restore it into new rehearsal volumes and prove that Auth users, notes, migration history, Storage metadata, and actual attachment bytes survive.
