Now we perform the restore rehearsal. Because your logical SQL dumps are useful for portability, we’ll also create a cold snapshot of the PostgreSQL volume. This gives us an exact disaster-recovery backup for the current image version.

## 1. Create cold volume snapshots

Ensure `BACKUP_DIR` is the absolute directory you used:

```zsh
BACKUP_DIR="/Users/user/Desktop/personal-supabase/backups/20260828T214328Z"
```

Stop the stack for a consistent snapshot:

```zsh
docker compose stop
```

Back up PostgreSQL:

```zsh
docker run --rm \
  -v supabase_supabase-db-data:/source:ro \
  -v "$BACKUP_DIR:/backup" \
  alpine:3.22 \
  tar -czf /backup/postgres-volume.tar.gz -C /source .
```

Back up Storage:

```zsh
docker run --rm \
  -v supabase_supabase-storage-data:/source:ro \
  -v "$BACKUP_DIR:/backup" \
  alpine:3.22 \
  tar -czf /backup/storage-volume.tar.gz -C /source .
```

Restart and confirm the original deployment:

```zsh
docker compose start
docker compose ps
```

Check both archives:

```zsh
ls -lh \
  "$BACKUP_DIR/postgres-volume.tar.gz" \
  "$BACKUP_DIR/storage-volume.tar.gz"

gzip -t "$BACKUP_DIR/postgres-volume.tar.gz" &&
  echo "PostgreSQL archive is valid"

gzip -t "$BACKUP_DIR/storage-volume.tar.gz" &&
  echo "Storage archive is valid"
```

## 2. Record verification values

Record counts without storing private content:

```zsh
psql "$SELF_HOSTED_DB_URL" \
  -Atc "
    select 'users=' || count(*) from auth.users;
    select 'notes=' || count(*) from public.notes;
    select 'objects=' || count(*)
    from storage.objects
    where bucket_id = 'note-attachments';
    select 'migrations=' || count(*)
    from supabase_migrations.schema_migrations;
  " \
  | tee "$BACKUP_DIR/expected-counts.txt"
```

## 3. Remove the working containers, preserving their volumes

This removes containers and networks, but not named volumes:

```zsh
docker compose down
```

Verify the original volumes remain:

```zsh
docker volume inspect \
  supabase_supabase-db-data \
  supabase_supabase-storage-data \
  >/dev/null &&
  echo "Original volumes preserved"
```

## 4. Create the isolated rehearsal deployment

Let Compose create fresh rehearsal containers and volumes:

```zsh
docker compose \
  --project-name supabase-restore \
  create
```

Confirm the new volumes:

```zsh
docker volume ls \
  --format '{{.Name}}' |
  grep '^supabase-restore_'
```

You should see at least:

```text
supabase-restore_supabase-db-data
supabase-restore_supabase-storage-data
```

Do not continue unless those names are present and different from the original `supabase_...` volumes.

## 5. Restore the archives into the fresh volumes

Restore PostgreSQL:

```zsh
docker run --rm \
  -v supabase-restore_supabase-db-data:/target \
  -v "$BACKUP_DIR:/backup:ro" \
  alpine:3.22 \
  tar -xzf /backup/postgres-volume.tar.gz -C /target
```

Restore Storage:

```zsh
docker run --rm \
  -v supabase-restore_supabase-storage-data:/target \
  -v "$BACKUP_DIR:/backup:ro" \
  alpine:3.22 \
  tar -xzf /backup/storage-volume.tar.gz -C /target
```

## 6. Start the restored deployment

```zsh
docker compose \
  --project-name supabase-restore \
  up -d
```

Watch its health:

```zsh
docker compose \
  --project-name supabase-restore \
  ps
```

If PostgreSQL does not become healthy, inspect:

```zsh
docker compose \
  --project-name supabase-restore \
  logs --tail=100 db
```

Once everything is healthy, we’ll compare the restored row counts, sign Roman in, read his notes, and download a restored attachment. Do not run `down -v`; we need the rehearsal volumes until verification is complete.
