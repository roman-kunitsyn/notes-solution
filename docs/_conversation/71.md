Library choice

I recommend **aiogram** for `apps/notes-bot/`.

The decisive reason is Python 3.14:

- aiogram added explicit Python 3.14 support in version 3.23.0.
- Current aiogram is asynchronous and supports long polling.
- `python-telegram-bot` is maintained, but its documentation still says Python 3.14 is not officially supported.

Sources: [aiogram changelog](https://docs.aiogram.dev/en/v3.25.0/changelog.html), [aiogram documentation](https://docs.aiogram.dev/), [Telegram long polling](https://core.telegram.org/bots/api#getupdates).

Authentication design

A Telegram user ID is only a Telegram identity. It must never be interpreted as a Supabase user ID.

For the first local slice, I recommend Supabase email OTP:

1. `/start` explains that Supabase authentication is required.
2. User submits their Supabase email.
3. Bot asks Supabase Auth to send an email OTP.
4. User sends the OTP to the bot.
5. Bot verifies it with Supabase Auth.
6. Only after successful verification does the bot associate:
   `telegram_user_id → Supabase refreshable session`
7. Every notes request uses that user’s Supabase JWT.
8. Existing `auth.uid()` RLS determines which notes are accessible.

This gives us the important property:

> Possession of a Telegram account alone cannot grant access to a Supabase account.

The bot must not use a service-role key for note operations. Supabase Auth issues a user JWT, and that JWT scopes REST requests through RLS. [Supabase documents this exact Auth/RLS relationship](https://supabase.com/docs/guides/auth), while unauthenticated requests have `auth.uid() = null` and cannot pass ownership policies ([RLS documentation](https://supabase.com/docs/guides/database/postgres/row-level-security)).

First vertical slice

After authentication:

- `/start` — introduction or authenticated status
- `/new Title | Content` — create a note without sending `user_id`
- `/notes` — list the authenticated user’s recent notes
- email + OTP conversation — establish the Supabase session

For local development, long polling is sufficient. No webhook, public URL, VPS, Caddy, or deployment changes are needed.

I also agree that we should not extract `packages/notes-python` now. Initially, the bot may repeat a small amount of Supabase client setup and note mapping. Once both applications exist, we can compare real duplication and extract only stable shared behavior.
