The HTTP implementation works. Pytest is mistakenly collecting the helper function `test_client()` as a test because its name begins with `test_`.

That helper expects `database_path` as a normal argument, but pytest interprets it as a fixture name.

## Fix

In `tests/test_http_server.py`, rename:

```python
@asynccontextmanager
async def test_client(
    database_path: Path,
) -> AsyncIterator[TestClient]:
```

to:

```python
@asynccontextmanager
async def http_test_client(
    database_path: Path,
) -> AsyncIterator[TestClient]:
```

Then replace every usage:

```python
async with test_client(
```

with:

```python
async with http_test_client(
```

There should be six replacements.

```bash

uv run ruff format --check .
uv run ruff check .

uv run pytest \
  tests/test_http_server.py \
  tests/test_linking.py \
  -v
```

Expected result:

```text

```

Then run the complete suite:

```bash
uv run pytest
git diff --check
```

No production code needs changing. This was purely a pytest test-discovery naming collision.
