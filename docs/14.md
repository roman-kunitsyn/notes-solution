The connection is correct; Supabase CLI tries TLS by default, while our local Supavisor endpoint has no TLS. Add `sslmode=disable` to the URL.

Rebuild it:

```bash
SELF_HOSTED_DB_URL="postgresql://postgres.${SELF_HOSTED_TENANT_ID}:${SELF_HOSTED_DB_PASSWORD}@127.0.0.1:5432/postgres?sslmode=disable"
```

Test:

```bash
psql "$SELF_HOSTED_DB_URL" \
  -c "select current_database(), current_user;"
```

Then retry:

```bash
supabase migration list \
  --db-url "$SELF_HOSTED_DB_URL"
```

And proceed:

```bash
supabase db push \
  --dry-run \
  --db-url "$SELF_HOSTED_DB_URL"
```

If the dry run is correct:

```bash
supabase db push \
  --db-url "$SELF_HOSTED_DB_URL"
```

This is appropriate only because the connection is local:

```text
127.0.0.1 → local Supavisor
```

On a real server, we will not expose an unencrypted PostgreSQL connection publicly. We’ll use either an SSH tunnel, a private network, or properly configured TLS.
