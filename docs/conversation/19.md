Now we test the complete application boundary:

```text
Auth token → REST note → private Storage object → RLS authorization
```

Use `ANON_KEY` for these requests—never `SERVICE_ROLE_KEY`, because service-role access would bypass RLS.

## 1. Load the self-hosted configuration

```bash
cd /Users/user/Desktop/personal-supabase/deploy/self-hosted

set -a
source .env
set +a

SUPABASE_URL="http://127.0.0.1:8000"
```

Confirm the stack:

```bash
docker compose ps
```

## 2. Sign in as Roman and Alice

Adjust the email addresses if you used different ones:

```bash
ROMAN_EMAIL="roman@example.com"
ALICE_EMAIL="alice@example.com"

read -rsp "Roman password: " ROMAN_PASSWORD
printf '\n'

read -rsp "Alice password: " ALICE_PASSWORD
printf '\n'
```

Get Roman’s token:

```bash
curl --fail-with-body -sS \
  -X POST "$SUPABASE_URL/auth/v1/token?grant_type=password" \
  -H "apikey: $ANON_KEY" \
  -H "Content-Type: application/json" \
  --data "$(jq -n \
    --arg email "$ROMAN_EMAIL" \
    --arg password "$ROMAN_PASSWORD" \
    '{email: $email, password: $password}')" \
  > /tmp/roman-login.json

ROMAN_TOKEN="$(jq -er '.access_token' /tmp/roman-login.json)"
ROMAN_ID="$(jq -er '.user.id' /tmp/roman-login.json)"
```

Get Alice’s token:

```bash
curl --fail-with-body -sS \
  -X POST "$SUPABASE_URL/auth/v1/token?grant_type=password" \
  -H "apikey: $ANON_KEY" \
  -H "Content-Type: application/json" \
  --data "$(jq -n \
    --arg email "$ALICE_EMAIL" \
    --arg password "$ALICE_PASSWORD" \
    '{email: $email, password: $password}')" \
  > /tmp/alice-login.json

ALICE_TOKEN="$(jq -er '.access_token' /tmp/alice-login.json)"
ALICE_ID="$(jq -er '.user.id' /tmp/alice-login.json)"
```

Verify that they are different users:

```bash
printf 'Roman: %s\nAlice: %s\n' "$ROMAN_ID" "$ALICE_ID"
```

## 3. Roman creates a note

Because the migration added `auth.uid()` as the default owner, we don’t send `user_id`:

```bash
curl --fail-with-body -sS \
  -X POST "$SUPABASE_URL/rest/v1/notes" \
  -H "apikey: $ANON_KEY" \
  -H "Authorization: Bearer $ROMAN_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Prefer: return=representation" \
  --data '{
    "title": "Attachment test",
    "content": "This note will have a private attachment."
  }' \
  > /tmp/roman-note.json

jq . /tmp/roman-note.json
```

Extract its ID and construct the required Storage path:

```bash
ROMAN_NOTE_ID="$(jq -er '.[0].id' /tmp/roman-note.json)"
ATTACHMENT_PATH="$ROMAN_ID/$ROMAN_NOTE_ID/example.txt"

printf '%s\n' "$ATTACHMENT_PATH"
```

It should have this shape:

```text
<roman-user-id>/<roman-note-id>/example.txt
```

## 4. Roman uploads the attachment

```bash
printf 'Roman private attachment, version 1.\n' \
  > /tmp/example.txt
```

Upload it:

```bash
curl --fail-with-body -sS \
  -X POST "$SUPABASE_URL/storage/v1/object/note-attachments/$ATTACHMENT_PATH" \
  -H "apikey: $ANON_KEY" \
  -H "Authorization: Bearer $ROMAN_TOKEN" \
  -H "Content-Type: text/plain" \
  --data-binary @/tmp/example.txt
```

Expected result: JSON containing the uploaded object path.

## 5. Roman downloads it

```bash
curl --fail-with-body -sS \
  "$SUPABASE_URL/storage/v1/object/authenticated/note-attachments/$ATTACHMENT_PATH" \
  -H "apikey: $ANON_KEY" \
  -H "Authorization: Bearer $ROMAN_TOKEN"
```

Expected:

```text
Roman private attachment, version 1.
```

## 6. Alice attempts to read Roman’s file

Here we intentionally avoid `--fail`, because failure is the expected result:

```bash
ALICE_READ_STATUS="$(
  curl -sS \
    -o /tmp/alice-read-response.json \
    -w '%{http_code}' \
    "$SUPABASE_URL/storage/v1/object/authenticated/note-attachments/$ATTACHMENT_PATH" \
    -H "apikey: $ANON_KEY" \
    -H "Authorization: Bearer $ALICE_TOKEN"
)"

printf 'HTTP status: %s\n' "$ALICE_READ_STATUS"
jq . /tmp/alice-read-response.json 2>/dev/null ||
  cat /tmp/alice-read-response.json
```

Expected: a non-2xx status, commonly `400`, `403`, or `404`. Supabase may deliberately hide whether the private object exists.

## 7. Alice attempts to upload into Roman’s folder

```bash
ALICE_UPLOAD_STATUS="$(
  curl -sS \
    -o /tmp/alice-upload-response.json \
    -w '%{http_code}' \
    -X POST "$SUPABASE_URL/storage/v1/object/note-attachments/$ATTACHMENT_PATH" \
    -H "apikey: $ANON_KEY" \
    -H "Authorization: Bearer $ALICE_TOKEN" \
    -H "Content-Type: text/plain" \
    -H "x-upsert: true" \
    --data-binary @/tmp/example.txt
)"

printf 'HTTP status: %s\n' "$ALICE_UPLOAD_STATUS"
jq . /tmp/alice-upload-response.json 2>/dev/null ||
  cat /tmp/alice-upload-response.json
```

This must also return non-2xx.

The denial has two independent reasons:

- the first path segment is Roman’s user ID;
- the referenced note belongs to Roman.

## 8. Roman replaces the attachment

```bash
printf 'Roman private attachment, version 2.\n' \
  > /tmp/example.txt
```

Upsert:

```bash
curl --fail-with-body -sS \
  -X POST "$SUPABASE_URL/storage/v1/object/note-attachments/$ATTACHMENT_PATH" \
  -H "apikey: $ANON_KEY" \
  -H "Authorization: Bearer $ROMAN_TOKEN" \
  -H "Content-Type: text/plain" \
  -H "x-upsert: true" \
  --data-binary @/tmp/example.txt
```

Download again:

```bash
curl --fail-with-body -sS \
  "$SUPABASE_URL/storage/v1/object/authenticated/note-attachments/$ATTACHMENT_PATH" \
  -H "apikey: $ANON_KEY" \
  -H "Authorization: Bearer $ROMAN_TOKEN"
```

Expected:

```text
Roman private attachment, version 2.
```

This confirms that all three upsert permissions work: `INSERT`, `SELECT`, and `UPDATE`.

## 9. Roman deletes the attachment

Storage’s bulk-delete endpoint accepts an array of paths:

```bash
curl --fail-with-body -sS \
  -X DELETE "$SUPABASE_URL/storage/v1/object/note-attachments" \
  -H "apikey: $ANON_KEY" \
  -H "Authorization: Bearer $ROMAN_TOKEN" \
  -H "Content-Type: application/json" \
  --data "$(jq -n --arg path "$ATTACHMENT_PATH" '{prefixes: [$path]}')"
```

Verify that it is gone:

```bash
curl -sS \
  -o /tmp/deleted-object-response.json \
  -w 'HTTP status: %{http_code}\n' \
  "$SUPABASE_URL/storage/v1/object/authenticated/note-attachments/$ATTACHMENT_PATH" \
  -H "apikey: $ANON_KEY" \
  -H "Authorization: Bearer $ROMAN_TOKEN"
```

Expected: non-2xx, normally `400` or `404`.

## 10. Remove temporary credentials

```bash
unset ROMAN_PASSWORD ALICE_PASSWORD
unset ROMAN_TOKEN ALICE_TOKEN

rm -f \
  /tmp/roman-login.json \
  /tmp/alice-login.json \
  /tmp/roman-note.json \
  /tmp/example.txt \
  /tmp/alice-read-response.json \
  /tmp/alice-upload-response.json \
  /tmp/deleted-object-response.json
```

If all checks pass, we have verified real end-to-end authorization for Database, Auth, REST, and Storage—not merely that the SQL migration exists.

Official reference: [Supabase Storage access control](https://supabase.com/docs/guides/storage/security/access-control). The next infrastructure stage will be deploying this reproducible stack onto a real Linux VPS.
