The Supabase CLI resolves `--file` relative to the Supabase project root, while your shell created the directory relative to `deploy/self-hosted`. That produced two different interpretations of:

```text
../../backups/...
```

Fix it by converting the directory to an absolute path immediately:

```zsh
BACKUP_ID="$(date -u +%Y%m%dT%H%M%SZ)"
BACKUP_DIR="../../backups/$BACKUP_ID"

mkdir -p "$BACKUP_DIR"

BACKUP_DIR="$(cd "$BACKUP_DIR" && pwd -P)"

printf 'Backup directory: %s\n' "$BACKUP_DIR"
```

Now `BACKUP_DIR` will contain something like:

```text
/Users/user/Desktop/personal-supabase/backups/20260828T214328Z
```

Every program will interpret it identically:

```zsh
supabase db dump \
  --db-url "$SELF_HOSTED_DB_URL" \
  --file "$BACKUP_DIR/roles.sql" \
  --role-only
```

In Zsh, there is also a compact path-expansion form:

```zsh
BACKUP_DIR="${BACKUP_DIR:A}"
```

But this version is more portable across shells:

```zsh
BACKUP_DIR="$(cd "$BACKUP_DIR" && pwd -P)"
```

Your manual absolute-path fix was therefore correct. Nothing is wrong with the dump itself—the failure occurred before Supabase created the output files.
