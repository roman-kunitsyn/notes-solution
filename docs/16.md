We’ll now create Roman and Alice through Auth, then use their JWTs against the REST API.

## 1. Enable local email auto-confirmation

For this local experiment, edit:

```bash
nvim deploy/self-hosted/.env
```

Set:

```dotenv
ENABLE_EMAIL_SIGNUP=true
ENABLE_EMAIL_AUTOCONFIRM=true
```

Recreate Auth:

```bash
cd deploy/self-hosted
sh run.sh recreate auth
docker compose ps auth
cd ../..
```

Before exposing this stack publicly, we will change auto-confirm back to `false` and configure SMTP.

## 2. Load the public API configuration

From `personal-supabase`:

```bash
SELF_HOSTED_ENV="deploy/self-hosted/.env"
SUPABASE_URL="http://localhost:8000"

SUPABASE_PUBLISHABLE_KEY="$(
  sed -n 's/^SUPABASE_PUBLISHABLE_KEY=//p' "$SELF_HOSTED_ENV"
)"
```

Verify without printing the key:

```bash
test -n "$SUPABASE_PUBLISHABLE_KEY" \
  && echo "Publishable key loaded"
```

## 3. Choose test passwords

The input will not be displayed:

```bash
read -rsp "Roman password: " ROMAN_PASSWORD
echo

read -rsp "Alice password: " ALICE_PASSWORD
echo
```

Use passwords of at least eight characters.

## 4. Register Roman

```bash
jq -n \
  --arg email "roman@example.test" \
  --arg password "$ROMAN_PASSWORD" \
  '{email: $email, password: $password}' \
| curl -sS \
    -X POST "$SUPABASE_URL/auth/v1/signup" \
    -H "apikey: $SUPABASE_PUBLISHABLE_KEY" \
    -H "Content-Type: application/json" \
    --data-binary @- \
> /tmp/roman-signup.json
```

Inspect only the safe summary:

```bash
jq '{
  user_id: .user.id,
  email: .user.email,
  has_access_token: (.access_token != null),
  error: (.error_description // .msg // .message // null)
}' /tmp/roman-signup.json
```

Expected:

```json
{
  "user_id": "...",
  "email": "roman@example.test",
  "has_access_token": true,
  "error": null
}
```

## 6. Load user IDs and tokens

```bash
ROMAN_ID="$(jq -r '.user.id' /tmp/roman-signup.json)"
ROMAN_TOKEN="$(jq -r '.access_token' /tmp/roman-signup.json)"

ALICE_ID="$(jq -r '.user.id' /tmp/alice-signup.json)"
ALICE_TOKEN="$(jq -r '.access_token' /tmp/alice-signup.json)"
```

Validate them without printing:

```bash
test -n "$ROMAN_ID" \
  && test "$ROMAN_TOKEN" != "null" \
  && echo "Roman session ready"

test -n "$ALICE_ID" \
  && test "$ALICE_TOKEN" != "null" \
  && echo "Alice session ready"
```

## 7. Create profiles through REST

Roman:

```bash
jq -n \
  --arg id "$ROMAN_ID" \
  '{id: $id, username: "roman"}' \
| curl -sS \
    -X POST "$SUPABASE_URL/rest/v1/profiles" \
    -H "apikey: $SUPABASE_PUBLISHABLE_KEY" \
    -H "Authorization: Bearer $ROMAN_TOKEN" \
    -H "Content-Type: application/json" \
    -H "Prefer: return=representation" \
```

## 9. Prove read isolation

As Roman:

```bash
curl -sS \
  "$SUPABASE_URL/rest/v1/notes?select=id,title,user_id&order=created_at" \
  -H "apikey: $SUPABASE_PUBLISHABLE_KEY" \
  -H "Authorization: Bearer $ROMAN_TOKEN" \
| jq
```

Roman should see exactly one note: `Roman self-hosted note`.

As Alice:

```bash
curl -sS \
  "$SUPABASE_URL/rest/v1/notes?select=id,title,user_id&order=created_at" \
  -H "apikey: $SUPABASE_PUBLISHABLE_KEY" \
  -H "Authorization: Bearer $ALICE_TOKEN" \
| jq
```

Alice should see exactly one note: `Alice private note`.

## 10. Prove Roman cannot create data for Alice

```bash
jq -n \
  --arg alice_id "$ALICE_ID" \
  '{
    user_id: $alice_id,
    title: "Forbidden cross-user note"
  }' \
| curl -sS \
    -o /tmp/forbidden-note.json \
    -w "HTTP status: %{http_code}\n" \
    -X POST "$SUPABASE_URL/rest/v1/notes" \
    -H "apikey: $SUPABASE_PUBLISHABLE_KEY" \
    -H "Authorization: Bearer $ROMAN_TOKEN" \
    -H "Content-Type: application/json" \
    --data-binary @-
```

Expected status:

```text
HTTP status: 403
```

Inspect the error:

```bash
jq . /tmp/forbidden-note.json
```

It should report a row-level security violation.

## 11. Prove anonymous access is denied

```bash
curl -sS \
  -o /tmp/anonymous-notes.json \
  -w "HTTP status: %{http_code}\n" \
  "$SUPABASE_URL/rest/v1/notes?select=id,title" \
  -H "apikey: $SUPABASE_PUBLISHABLE_KEY"
```

Because we granted table access only to `authenticated`, anonymous access should return an authorization error rather than note data.

## 12. Remove token files and variables

These temporary files contain live access tokens:

```bash
rm -f \
  /tmp/roman-signup.json \
  /tmp/alice-signup.json \
  /tmp/forbidden-note.json \
  /tmp/anonymous-notes.json
```

Clear the shell variables:

```bash
unset ROMAN_PASSWORD ALICE_PASSWORD
unset ROMAN_TOKEN ALICE_TOKEN
unset ROMAN_ID ALICE_ID
unset SUPABASE_PUBLISHABLE_KEY SUPABASE_URL SELF_HOSTED_ENV
```

We have now exercised the complete self-hosted security path. The next engineering improvement should be a new migration that makes `notes.user_id` and `tags.user_id` default to `auth.uid()`, so clients do not need to send or control ownership IDs themselves.
