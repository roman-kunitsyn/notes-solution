Next we prepare the HTTPS layer using Supabase’s bundled Caddy configuration. It will remain disabled locally and will not request certificates.

One correction from the earlier placeholder configuration: `API_EXTERNAL_URL` must include `/auth/v1`.

## 1. Confirm the bundled Caddy configuration

```zsh
test -f docker-compose.caddy.yml &&
  echo "Caddy Compose override found"

test -f volumes/proxy/caddy/Caddyfile &&
  echo "Caddyfile found"
```

Inspect it:

```zsh
sed -n '1,200p' docker-compose.caddy.yml
sed -n '1,200p' volumes/proxy/caddy/Caddyfile
```

We’ll use these official files instead of maintaining our own reverse-proxy implementation.

## 2. Add proxy configuration placeholders

Open:

```zsh
nvim .env.production
```

Ensure the URL section has this shape:

```dotenv
# Supabase API domain
PROXY_DOMAIN=api.example.com

# External Supabase URL
SUPABASE_PUBLIC_URL=https://api.example.com

# Auth API base URL; /auth/v1 is required
API_EXTERNAL_URL=https://api.example.com/auth/v1

# Future Notes client—not the Supabase API
SITE_URL=https://app.example.com

# Allowed Auth redirect targets
ADDITIONAL_REDIRECT_URLS=https://app.example.com/**
```

Also add the same variable names to `.env.production.example`, retaining placeholder values.

The distinction is:

| Variable                   | Future value                              |
| -------------------------- | ----------------------------------------- |
| `PROXY_DOMAIN`             | Supabase API hostname                     |
| `SUPABASE_PUBLIC_URL`      | Public Supabase base URL                  |
| `API_EXTERNAL_URL`         | Public Auth base URL ending in `/auth/v1` |
| `SITE_URL`                 | Notes client URL                          |
| `ADDITIONAL_REDIRECT_URLS` | Permitted application callbacks           |

## 3. Validate the complete HTTPS deployment

This includes base Supabase, our Linux production override, and Caddy:

```zsh
docker compose \
  --env-file .env.production \
  --file docker-compose.yml \
  --file docker-compose.production.yml \
  --file docker-compose.caddy.yml \
  config --quiet
```

Render it:

```zsh
docker compose \
  --env-file .env.production \
  --file docker-compose.yml \
  --file docker-compose.production.yml \
  --file docker-compose.caddy.yml \
  config \
  > /tmp/supabase-production-https.yml
```

## 4. Inspect public ports

```zsh
grep -nE \
  'host_ip:|published:|target:' \
  /tmp/supabase-production-https.yml
```

The intended exposure is:

| Port   | Binding     | Purpose                                    |
| ------ | ----------- | ------------------------------------------ |
| `80`   | Public      | HTTP redirect and certificate validation   |
| `443`  | Public      | HTTPS API, Auth, Storage, Studio, Realtime |
| `8000` | `127.0.0.1` | Direct local Envoy access                  |
| `5432` | `127.0.0.1` | PostgreSQL session connection              |
| `6543` | `127.0.0.1` | PostgreSQL transaction connection          |

No PostgreSQL port should bind to `0.0.0.0`.

## 5. Confirm Caddy persistence

```zsh
docker compose \
  --env-file .env.production \
  --file docker-compose.yml \
  --file docker-compose.production.yml \
  --file docker-compose.caddy.yml \
  config --volumes
```

In addition to the database and Storage volumes, expect Caddy volumes for certificate state. Their exact names depend on the bundled file.

## 6. Add an HTTPS validation command

In `scripts/production.sh`, add near the existing variable declarations:

```sh
CADDY_COMPOSE_FILE="docker-compose.caddy.yml"
```

Add this case before `help)`:

```sh
  validate-https)
    docker compose \
      --env-file "$ENV_FILE" \
      --file "$COMPOSE_FILE" \
      --file "$PRODUCTION_COMPOSE_FILE" \
      --file "$CADDY_COMPOSE_FILE" \
      config --quiet

    echo "Production HTTPS configuration is valid"
    ;;
```

Add its help line:

```sh
echo "  validate-https  Validate Supabase with the Caddy HTTPS layer"
```

Test it:

```zsh
scripts/production.sh validate-https
```

This does not start Caddy or contact Let’s Encrypt.

We now have the HTTPS topology ready. On the VPS, the only missing actions will be replacing `example.com`, pointing DNS, opening ports `80` and `443`, and starting Caddy. It will provision and renew certificates automatically. [Supabase HTTPS proxy guide](https://supabase.com/docs/guides/self-hosting/self-hosted-proxy-https).
