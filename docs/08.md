We should not reset again yet. The important new fact is:

```text
role "postgres" does not exist
```

That means PostgreSQL initialization itself did not produce the role set expected by this Compose configuration. Let’s inspect the initialization without exposing secrets.

From `deploy/self-hosted`:

## 1. Stop the restarting application services

Leave PostgreSQL running, but stop the noisy dependent services:

```bash
docker compose stop auth rest realtime storage meta supavisor
```

## 2. Check which Compose configuration is active

```bash
grep -E \
  '^(COMPOSE_FILE|POSTGRES_HOST|POSTGRES_PORT|POSTGRES_DB|POSTGRES_USER_READ_WRITE)=' \
  .env
```

Also run:

```bash
docker compose config --services
```

If `COMPOSE_FILE` contains an unexpected override such as a read-only or external-database configuration, that may explain the missing role.

## 3. Verify the actual mounted database directory

```bash
docker inspect supabase-db \
  --format '{{range .Mounts}}{{println .Source "->" .Destination}}{{end}}'
```

Find the line ending with:

```text
-> /var/lib/postgresql/data
```

Its source must point to:

```text
personal-supabase/deploy/self-hosted/volumes/db/data
```

If it points to the old source clone or another directory, we cleaned the wrong database directory.

## 4. List the roles using the actual administrator

The current image appears to have initialized with `supabase_admin` as its bootstrap administrator. Try:

```bash
docker exec supabase-db \
  psql -U supabase_admin -d postgres \
  -c "
    select
      rolname,
      rolsuper,
      rolcanlogin
    from pg_roles
    where rolname in (
      'postgres',
      'supabase_admin',
      'supabase_auth_admin',
      'supabase_storage_admin',
      'authenticator'
    )
    order by rolname;
  "
```

If `postgres` is absent but the other roles exist, we have an inconsistent role initialization rather than an empty database.

## 5. Inspect database initialization errors

```bash
docker logs supabase-db 2>&1 \
  | grep -Ei 'error|fatal|role|password|initdb|ready'
```

Also check that the initialization scripts were mounted:

```bash
docker exec supabase-db \
  find /docker-entrypoint-initdb.d \
  -maxdepth 2 \
  -type f \
  -print
```

We should see scripts including:

```text
98-webhooks.sql
99-roles.sql
99-jwt.sql
97-_supabase.sql
99-pooler.sql
```

## 6. Do not use `db-passwd.sh` yet

That script executes:

```sql
alter user postgres ...
```

Because `postgres` currently does not exist, the script would stop partway through and would not reliably fix this state.

Likewise, the `401 Unauthorized` from:

```text
http://localhost:8000/auth/v1/health
```

is not currently useful. Envoy is alive, but Auth is restarting, and the gateway route may also expect an API key.

The Basic Auth login working proves only this path:

```text
browser → Envoy → Studio
```

The Studio error proves this path remains broken:

```text
Studio → postgres-meta → PostgreSQL
```
