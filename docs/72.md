For a production-grade bot, we should begin with authentication design—not scaffolding.

The secure model should be:

1. Telegram identifies the Telegram account only.
2. The user opens a one-time HTTPS linking URL from the bot.
3. The user authenticates with Supabase Auth in a browser.
4. A successful Supabase session is linked to the pending Telegram identity.
5. The bot stores the refresh token encrypted at rest.
6. Every Notes request uses that user’s Supabase session.
7. Existing RLS remains responsible for authorization.
8. The bot never uses a service-role key for Notes operations.

I no longer recommend asking users to paste email OTP codes into Telegram for the production design. It is workable for an experiment, but browser-based linking is cleaner and avoids teaching users to send authentication codes to a bot.
