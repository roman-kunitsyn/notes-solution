We’ll create a second migration locally, test it, then deploy it without losing the existing self-hosted users or notes.

## 1. Stop self-hosted and start development

```bash
cd deploy/self-hosted
sh run.sh stop
cd ../..

supabase start
```

The self-hosted named volume remains intact.

## 2. Create the migration

```bash
supabase migration new add_ownership_defaults
```

Open it:

```bash
nvim supabase/migrations/*_add_ownership_defaults.sql
```

Add:

```sql
-- Clients should not need to send their own ownership identifiers.
-- RLS still prevents users from explicitly supplying another user's ID.

alter table public.profiles
alter column id set default auth.uid();

alter table public.notes
alter column user_id set default auth.uid();

alter table public.tags
alter column user_id set default auth.uid();
```

This improves the API. A client can now submit:

```json
{
  "title": "My note",
  "content": "The server determines its owner."
}
```

instead of sending `user_id`.

## 3. Add a database test

Create:

```bash
touch supabase/tests/database/ownership_defaults_test.sql
nvim supabase/tests/database/ownership_defaults_test.sql
```

Paste:

```sql
begin;

select plan(5);

-- Create a temporary Auth user before switching to the authenticated role.

insert into auth.users (
  instance_id,
  id,
  aud,
  role,
  email,
  email_confirmed_at,
  raw_app_meta_data,
  raw_user_meta_data,
  created_at,
  updated_at
)
values (
  '00000000-0000-0000-0000-000000000000',
  '50000000-0000-0000-0000-000000000005',
  'authenticated',
  'authenticated',
  'ownership-test@example.test',
  now(),
  '{"provider":"email","providers":["email"]}'::jsonb,
  '{}'::jsonb,
  now(),
  now()
);

set local role authenticated;

select set_config(
  'request.jwt.claims',
  '{
    "sub": "50000000-0000-0000-0000-000000000005",
    "role": "authenticated"
  }',
  true
);


-- 1. Profile ID defaults to auth.uid().

select results_eq(
  $$
    insert into public.profiles (username)
    values ('ownership-test-user')
    returning id
  $$,
  $$
    values ('50000000-0000-0000-0000-000000000005'::uuid)
  $$,
  'profile ID defaults to auth.uid()'
);


-- 2. Note owner defaults to auth.uid().

select results_eq(
  $$
    insert into public.notes (title, content)
    values ('Default owner note', 'No user_id was supplied')
    returning user_id
  $$,
  $$
    values ('50000000-0000-0000-0000-000000000005'::uuid)
  $$,
  'note user_id defaults to auth.uid()'
);


-- 3. Tag owner defaults to auth.uid().

select results_eq(
  $$
    insert into public.tags (name)
    values ('automatic-owner')
    returning user_id
  $$,
  $$
    values ('50000000-0000-0000-0000-000000000005'::uuid)
  $$,
  'tag user_id defaults to auth.uid()'
);


-- 4. Explicitly assigning Alice as note owner remains forbidden.

select throws_ok(
  $$
    insert into public.notes (user_id, title)
    values (
      '20000000-0000-0000-0000-000000000002',
      'Forbidden Alice note'
    )
  $$,
  '42501',
  'new row violates row-level security policy for table "notes"',
  'user cannot override note ownership'
);


-- 5. Explicitly assigning Alice as tag owner remains forbidden.

select throws_ok(
  $$
    insert into public.tags (user_id, name)
    values (
      '20000000-0000-0000-0000-000000000002',
      'forbidden-tag'
    )
  $$,
  '42501',
  'new row violates row-level security policy for table "tags"',
  'user cannot override tag ownership'
);

select * from finish();

rollback;
```

## 4. Reconstruct and test locally

```bash
supabase db reset
supabase test db
supabase db advisors
```

Both test files should pass.

Verify the defaults:

```bash
psql \
  postgresql://postgres:postgres@127.0.0.1:54322/postgres \
  -c "
    select
      table_name,
      column_name,
      column_default
    from information_schema.columns
    where table_schema = 'public'
      and (
        (table_name = 'profiles' and column_name = 'id')
        or
        (table_name = 'notes' and column_name = 'user_id')
        or
        (table_name = 'tags' and column_name = 'user_id')
      )
    order by table_name;
  "
```

## 5. Commit the tested change

```bash
git add supabase/migrations supabase/tests
git commit -m "Default resource ownership to authenticated user"
```

## 6. Switch back to self-hosted

```bash
supabase stop

cd deploy/self-hosted
sh run.sh start
docker compose ps
cd ../..
```

Existing self-hosted users and notes should still exist because we preserved the named database volume.

## 7. Rebuild the connection URL

```bash
SELF_HOSTED_ENV="deploy/self-hosted/.env"

SELF_HOSTED_TENANT_ID="$(
  sed -n 's/^POOLER_TENANT_ID=//p' "$SELF_HOSTED_ENV"
)"

SELF_HOSTED_DB_PASSWORD="$(
  sed -n 's/^POSTGRES_PASSWORD=//p' "$SELF_HOSTED_ENV"
)"

SELF_HOSTED_DB_URL="postgresql://postgres.${SELF_HOSTED_TENANT_ID}:${SELF_HOSTED_DB_PASSWORD}@127.0.0.1:5432/postgres?sslmode=disable"
```

## 8. Deploy incrementally

Preview:

```bash
supabase db push \
  --dry-run \
  --db-url "$SELF_HOSTED_DB_URL"
```

It should show only:

```text
<timestamp>_add_ownership_defaults.sql
```

Apply:

```bash
supabase db push \
  --db-url "$SELF_HOSTED_DB_URL"
```

Verify history:

```bash
supabase migration list \
  --db-url "$SELF_HOSTED_DB_URL"
```

Both migrations should appear in local and remote columns.

## 9. Verify self-hosted defaults

```bash
psql "$SELF_HOSTED_DB_URL" \
  -c "
    select
      table_name,
      column_name,
      column_default
    from information_schema.columns
    where table_schema = 'public'
      and (
        (table_name = 'profiles' and column_name = 'id')
        or
        (table_name = 'notes' and column_name = 'user_id')
        or
        (table_name = 'tags' and column_name = 'user_id')
      )
    order by table_name;
  "
```

The defaults should reference `auth.uid()`.

Finally:

```bash
unset SELF_HOSTED_DB_URL
unset SELF_HOSTED_DB_PASSWORD
unset SELF_HOSTED_TENANT_ID
unset SELF_HOSTED_ENV
```

This completes our first proper development cycle:

```text
migration → local reset → tests → commit → dry run → production push
```
