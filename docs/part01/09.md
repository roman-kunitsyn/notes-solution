## 1. Check whether the mounted SQL is readable

Run:

```bash
docker exec supabase-db \
  sh -c 'ls -l /docker-entrypoint-initdb.d/init-scripts'
```

Then:

```bash
docker exec supabase-db \
  sh -c 'sed -n "1,40p" /docker-entrypoint-initdb.d/init-scripts/99-roles.sql'
```

You should see actual SQL, not an empty file or directory.

Check file type and line endings:

```bash
file volumes/db/roles.sql
```

Expected:

```text
ASCII text
```

or:

```text
Unicode text, UTF-8 text
```

It should not say:

```text
with CRLF line terminators
```

## 3. Test the roles script inside a transaction

Do not apply it permanently yet. Ask PostgreSQL to parse and execute it, then roll everything back:

```bash
docker exec -i supabase-db \
  psql \
    -U supabase_admin \
    -d postgres \
    -v ON_ERROR_STOP=1 \
    -v pgpass="$POSTGRES_PASSWORD" <<'SQL'
begin;

\i /docker-entrypoint-initdb.d/init-scripts/99-roles.sql

rollback;
SQL
```

There is one problem with that command: `$POSTGRES_PASSWORD` belongs to the container environment, while interpolation above happens on your Mac. Use this container-side version instead:

```bash
docker exec supabase-db sh -c '
  psql \
    -U supabase_admin \
    -d postgres \
    -v ON_ERROR_STOP=1 \
    --set=pgpass="$POSTGRES_PASSWORD" \
    --file=/docker-entrypoint-initdb.d/init-scripts/99-roles.sql
'
```

However, this second command applies the roles permanently. Since the database is empty, that is acceptable—but first inspect the database logs and file contents above.
