The next step is private file attachments for notes using Supabase Storage and RLS.

We’ll do it entirely through a migration—nothing manually in Studio. This stage creates the bucket and policies; after it deploys successfully, we’ll test the real Storage HTTP API as Roman and Alice.

## 1. Start the local development stack

If the self-hosted stack is currently running:

```bash
cd /Users/user/Desktop/personal-supabase/deploy/self-hosted
docker compose down
```

Then:

```bash
cd /Users/user/Desktop/personal-supabase
supabase start
```

## 2. Create the migration

```bash
supabase migration new create_note_attachments
```

Open the newly created file:

```text
supabase/migrations/<timestamp>_create_note_attachments.sql
```

Put this into it:

```sql
-- Private Storage bucket for note attachments.
--
-- Required object path:
--   <user-id>/<note-id>/<filename>
--
-- Example:
--   81b8.../d921.../requirements.pdf

insert into storage.buckets (
  id,
  name,
  public,
  file_size_limit,
  allowed_mime_types
)
values (
  'note-attachments',
  'note-attachments',
  false,
  10485760, -- 10 MiB
  array[
    'image/png',
    'image/jpeg',
    'application/pdf',
    'text/plain'
  ]::text[]
)
on conflict (id) do update
set
  name = excluded.name,
  public = excluded.public,
  file_size_limit = excluded.file_size_limit,
  allowed_mime_types = excluded.allowed_mime_types;


-- Read/download only attachments belonging to one of the user's notes.
create policy "note attachments select own"
on storage.objects
for select
to authenticated
using (
  bucket_id = 'note-attachments'
  and coalesce(array_length(storage.foldername(name), 1), 0) = 2
  and (storage.foldername(name))[1] = (select auth.uid())::text
  and exists (
    select 1
    from public.notes
    where notes.id::text = (storage.foldername(name))[2]
      and notes.user_id = (select auth.uid())
  )
);


-- Upload only into the authenticated user's folder and an owned note.
create policy "note attachments insert own"
on storage.objects
for insert
to authenticated
with check (
  bucket_id = 'note-attachments'
  and coalesce(array_length(storage.foldername(name), 1), 0) = 2
  and (storage.foldername(name))[1] = (select auth.uid())::text
  and exists (
    select 1
    from public.notes
    where notes.id::text = (storage.foldername(name))[2]
      and notes.user_id = (select auth.uid())
  )
);


-- Required for replacing/upserting an existing attachment.
create policy "note attachments update own"
on storage.objects
for update
to authenticated
using (
  bucket_id = 'note-attachments'
  and coalesce(array_length(storage.foldername(name), 1), 0) = 2
  and (storage.foldername(name))[1] = (select auth.uid())::text
  and exists (
    select 1
    from public.notes
    where notes.id::text = (storage.foldername(name))[2]
      and notes.user_id = (select auth.uid())
  )
)
with check (
  bucket_id = 'note-attachments'
  and coalesce(array_length(storage.foldername(name), 1), 0) = 2
  and (storage.foldername(name))[1] = (select auth.uid())::text
  and exists (
    select 1
    from public.notes
    where notes.id::text = (storage.foldername(name))[2]
      and notes.user_id = (select auth.uid())
  )
);


-- Delete only attachments belonging to one of the user's notes.
create policy "note attachments delete own"
on storage.objects
for delete
to authenticated
using (
  bucket_id = 'note-attachments'
  and coalesce(array_length(storage.foldername(name), 1), 0) = 2
  and (storage.foldername(name))[1] = (select auth.uid())::text
  and exists (
    select 1
    from public.notes
    where notes.id::text = (storage.foldername(name))[2]
      and notes.user_id = (select auth.uid())
  )
);
```

The filename can contain subdirectories only if we later adjust the policy. Right now, exactly this structure is accepted:

```text
user UUID / note UUID / filename
```

## 3. Rebuild and verify locally

This resets only the local CLI database:

```bash
supabase db reset
supabase test db
supabase db advisors
```

Check the bucket:

```bash
psql "$(supabase status -o env | sed -n 's/^DB_URL=//p' | tr -d '"')" \
  -c "
    select id, name, public, file_size_limit, allowed_mime_types
    from storage.buckets
    where id = 'note-attachments';
  "
```

Check the policies:

```bash
psql "$(supabase status -o env | sed -n 's/^DB_URL=//p' | tr -d '"')" \
  -c "
    select policyname, cmd, roles
    from pg_policies
    where schemaname = 'storage'
      and tablename = 'objects'
      and policyname like 'note attachments%'
    order by cmd;
  "
```

You should see:

- one private bucket;
- `SELECT`, `INSERT`, `UPDATE`, and `DELETE` policies;
- existing pgTAP tests passing.

## 4. Deploy it to self-hosted Supabase

Stop the local CLI stack:

```bash
supabase stop
```

Start self-hosted Supabase:

```bash
cd /Users/user/Desktop/personal-supabase/deploy/self-hosted
docker compose up -d
docker compose ps
```

Load the deployment configuration and construct the database URL:

```bash
set -a
source .env
set +a

SELF_HOSTED_DB_URL="postgresql://postgres.${POOLER_TENANT_ID}:${POSTGRES_PASSWORD}@127.0.0.1:5432/postgres?sslmode=disable"
```

Return to the repository root:

```bash
cd /Users/user/Desktop/personal-supabase
```

Compare migration histories:

```bash
supabase migration list \
  --db-url "$SELF_HOSTED_DB_URL"
```

Deploy:

```bash
supabase db push \
  --db-url "$SELF_HOSTED_DB_URL"
```

Verify:

```bash
supabase migration list \
  --db-url "$SELF_HOSTED_DB_URL"
```

Finally, confirm that Storage is healthy:

```bash
cd deploy/self-hosted

docker compose ps storage

docker compose logs \
  --tail=50 \
  storage
```

Do not upload files by inserting rows directly into `storage.objects`; file operations must go through the Storage API. Our next step will use real Roman and Alice access tokens to verify upload, download, replacement, deletion, and cross-user denial.

Official references: [Storage access control](https://supabase.com/docs/guides/storage/security/access-control), [creating buckets](https://supabase.com/docs/guides/storage/buckets/creating-buckets), and [Storage fundamentals](https://supabase.com/docs/guides/storage/buckets/fundamentals).
