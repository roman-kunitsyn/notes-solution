The failure is not filesystem state now. The connection-leak fix was applied too broadly.

`database_connection()` is a context manager, not a `sqlite3.Connection`. Therefore this is invalid:

```python
connection = database_connection(database_path)
connection.execute(...)
```

It returns `_GeneratorContextManager`, exactly as the traceback reports.

For this step, restore explicit transaction functions to `open_database()`.

### 1. Find the incorrect assignments

From `apps/notes-bot`:

```bash
rg -n "connection = database_connection" src tests
```

For every result using explicit `commit()`, `rollback()`, and `close()`, change:

```python
connection = database_connection(database_path)
```

back to:

```python
connection = open_database(database_path)
```

Keep the existing transaction structure:

```python
connection = open_database(database_path)

try:
    connection.execute("BEGIN IMMEDIATE")
    # transactional work
    connection.commit()
except Exception:
    connection.rollback()
    raise
finally:
    connection.close()
```

At minimum, the traceback shows corrections are required in:

- `consume_link_challenge()` in `linking.py`
- transactional functions in `otp_state.py`
- `complete_linked_session()` in `sessions.py`

Make sure those modules import `open_database` again.

### 2. Keep the wrapper only with `with`

Ordinary short database operations should continue using:

```python
with database_connection(database_path) as connection:
    ...
```

The rule is:

| Usage                                  | Function                                                             |
| -------------------------------------- | -------------------------------------------------------------------- |
| Ordinary read/write                    | `with database_connection(...) as connection:`                       |
| Explicit `BEGIN IMMEDIATE` transaction | `connection = open_database(...)` with `finally: connection.close()` |

Do not nest `BEGIN IMMEDIATE` inside `database_connection()` in this correction. Keeping the existing explicit transaction code is clearer and minimizes changes.

### 3. Fix the newer-schema test

The test must enter the context manager. A bare call such as this does not open the database:

```python
database_connection(path)
```

Use:

```python
with pytest.raises(
    DatabaseVersionError,
    match="newer than supported",
):
    with database_connection(path):
        pass
```

Entering the `with` block calls `open_database()`, which should detect the unsupported schema version.
