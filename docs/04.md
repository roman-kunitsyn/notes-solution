Now we’ll add reproducible development data and automated RLS tests. These users are database fixtures—not yet login-ready Auth accounts. We’ll test real authentication through the API later.

## 2. Rebuild and seed the database

```bash
supabase db reset
```

You should see both stages:

```text
Applying migration ..._create_notes_schema.sql...
Seeding data from supabase/seed.sql...
```

Check the data through `psql`:

```bash
psql postgresql://postgres:postgres@127.0.0.1:54322/postgres
```

Then:

```sql
select email from auth.users order by email;

select
  profiles.username,
  notes.title
from public.notes
join public.profiles
  on profiles.id = notes.user_id
order by profiles.username, notes.title;
```

Expected notes:

```text
alice | Alice private note
roman | Deploy Supabase
roman | Learn Supabase
```

Exit:

```text
\q
```

## 3. Create the database test

Create the standard test directory:

```bash
mkdir -p supabase/tests/database
touch supabase/tests/database/notes_rls_test.sql
nvim supabase/tests/database/notes_rls_test.sql
```

Paste:

```sql
begin;

select plan(8);

-- Act as Roman through the same JWT claims used by Supabase Auth.
set local role authenticated;

select set_config(
  'request.jwt.claims',
  '{
    "sub": "10000000-0000-0000-0000-000000000001",
    "role": "authenticated"
  }',
  true
);


-- 1. auth.uid() extracts Roman's ID from the simulated JWT.

select is(
  auth.uid(),
  '10000000-0000-0000-0000-000000000001'::uuid,
  'Roman is the authenticated user'
);


-- 2. Roman sees exactly his two initial notes.

select results_eq(
  $$
    select count(*)
    from public.notes
  $$,
  $$
    values (2::bigint)
  $$,
  'Roman sees exactly two notes'
);


-- 3. Alice's note is invisible to Roman.

select results_eq(
  $$
    select count(*)
    from public.notes
    where id = '30000000-0000-0000-0000-000000000003'
  $$,
  $$
    values (0::bigint)
  $$,
  'Roman cannot read Alice note'
);


-- 4. Roman can create a note owned by Roman.

select lives_ok(
  $$
    insert into public.notes (user_id, title, content)
    values (
      '10000000-0000-0000-0000-000000000001',
      'RLS test note',
      'Created during the pgTAP test'
    )
  $$,
  'Roman can create his own note'
);


-- 5. Roman cannot create a note owned by Alice.

select throws_ok(
  $$
    insert into public.notes (user_id, title)
    values (
      '20000000-0000-0000-0000-000000000002',
      'Forbidden note'
    )
  $$,
  '42501',
  'new row violates row-level security policy for table "notes"',
  'Roman cannot create a note for Alice'
);


-- 6. Roman can update his own note.

select lives_ok(
  $$
    update public.notes
    set title = 'Learn Supabase properly'
    where id = '30000000-0000-0000-0000-000000000001'
  $$,
  'Roman can update his own note'
);


-- 7. Updating Alice's note affects no rows because it is invisible.

select results_eq(
  $$
    update public.notes
    set title = 'Roman was here'
    where id = '30000000-0000-0000-0000-000000000003'
    returning id
  $$,
  $$
    select id
    from public.notes
    where false
  $$,
  'Roman cannot update Alice note'
);


-- 8. Roman cannot transfer his note to Alice.

select throws_ok(
  $$
    update public.notes
    set user_id = '20000000-0000-0000-0000-000000000002'
    where id = '30000000-0000-0000-0000-000000000001'
  $$,
  '42501',
  'new row violates row-level security policy for table "notes"',
  'Roman cannot transfer ownership to Alice'
);

select * from finish();

rollback;
```

The transaction is rolled back after the test, so the temporary test note and update do not remain in the database.

## 4. Run the tests

```bash
supabase test db
```

Expected result:

```text
supabase/tests/database/notes_rls_test.sql .. ok
All tests successful.
Result: PASS
```

If one test fails only because the PostgreSQL error text differs, show me the exact output. We’ll adjust the assertion without weakening the security check.

## 5. Verify the seed remains unchanged

```bash
psql \
  postgresql://postgres:postgres@127.0.0.1:54322/postgres \
  -c "select title from public.notes order by title;"
```

There should still be only three notes. This proves the tests are isolated.

## 6. Commit

```bash
git add supabase/seed.sql supabase/tests
git commit -m "Add notes seed data and RLS tests"
```

`seed.sql` is used by `supabase start` and `supabase db reset`, but it is not sent to production by an ordinary `supabase db push`. That separation is exactly what we want.

Official references: [Seeding your database](https://supabase.com/docs/guides/local-development/seeding-your-database) and [Testing your database with pgTAP](https://supabase.com/docs/guides/database/testing).
