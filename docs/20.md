The cause is the Storage bind mount:

```text
./volumes/storage → /var/lib/storage
```

On macOS with Colima, that path is shared through macOS filesystem virtualization, which does not provide the Linux extended attributes required by the Storage file backend.

Use a Docker named volume stored inside Colima’s Linux VM.

## 1. Update the Colima override

Open:

```text
deploy/self-hosted/docker-compose.colima.yml
```

It should now contain both database and Storage overrides:

```yaml
services:
  db:
    volumes:
      - supabase-db-data:/var/lib/postgresql/data

  storage:
    volumes:
      - supabase-storage-data:/var/lib/storage

volumes:
  supabase-db-data:
  supabase-storage-data:
```

Do not add another `services:` or `volumes:` section if they already exist—extend the existing ones.

## 2. Verify Compose sees the override

Your `.env` should still contain:

```env
COMPOSE_FILE=docker-compose.yml:docker-compose.colima.yml
```

Check the resolved Storage configuration:

```bash
docker compose config | grep -A12 'storage:'
```

## 3. Recreate only the Storage container

```bash
docker compose up -d --force-recreate storage
```

Check its status:

```bash
docker compose ps storage
docker compose logs --tail=50 storage
```

Verify the actual mount:

```bash
docker inspect supabase-storage \
  --format '{{range .Mounts}}{{println .Type .Name .Source "->" .Destination}}{{end}}'
```

For `/var/lib/storage`, you should now see `volume`, not `bind`, approximately:

```text
volume supabase_supabase-storage-data ... -> /var/lib/storage
```

The exact volume prefix can differ.

## 4. Retry Roman’s upload

Your failed upload should not have created a valid object, so retry the same request:

```bash
curl --fail-with-body -sS \
  -X POST "$SUPABASE_URL/storage/v1/object/note-attachments/$ATTACHMENT_PATH" \
  -H "apikey: $ANON_KEY" \
  -H "Authorization: Bearer $ROMAN_TOKEN" \
  -H "Content-Type: text/plain" \
  --data-binary @/tmp/example.txt
```

Expected result:

```json
{ "Key": "note-attachments/.../example.txt" }
```

Then download it:

```bash
curl --fail-with-body -sS \
  "$SUPABASE_URL/storage/v1/object/authenticated/note-attachments/$ATTACHMENT_PATH" \
  -H "apikey: $ANON_KEY" \
  -H "Authorization: Bearer $ROMAN_TOKEN"
```

Expected:

```text
Roman private attachment, version 1.
```

If the token expired while we were troubleshooting, sign Roman in again and update `ROMAN_TOKEN`; you do not need to recreate the note.

The official Compose configuration confirms that Storage persists `/var/lib/storage`; we are changing only the host-side storage mechanism for Colima compatibility: [official Supabase Docker Compose](https://github.com/supabase/supabase/blob/master/docker/docker-compose.yml) and [self-hosting documentation](https://supabase.com/docs/guides/self-hosting/docker).
