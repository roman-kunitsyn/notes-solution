## Step 6 — Review, commit, push, and verify CI

We now have one coherent change: the complete local Notes bot foundation.

### 1. Review the worktree

From the repository root:

```bash
cd /Users/user/Desktop/personal-supabase

git status --short
git diff --stat
git diff --check
```

Expected changes should be limited to:

- `.github/workflows/ci.yml`
- `apps/notes-bot/`

There should be no `.env`, build output, virtual environment, cache, or token file.

Inspect the actual changes:

```bash
git diff -- .github/workflows/ci.yml
git diff -- apps/notes-bot
```

Because `apps/notes-bot` is untracked, ordinary `git diff` might not show its contents yet. That is normal.

### 2. Stage only this milestone

```bash
git add \
  .github/workflows/ci.yml \
  apps/notes-bot
```

Review the staged files:

```bash
git status --short
git diff --cached --stat
git diff --cached --check
```

Inspect the complete staged patch:

```bash
git diff --cached
```

Check specifically that these are absent:

- `.env`
- `.venv/`
- `dist/`
- `__pycache__/`
- `.pytest_cache/`
- `.ruff_cache/`
- real Telegram token

You can list staged filenames with:

```bash
git diff --cached --name-only
```

### 3. Run the final validation

```bash
cd apps/notes-bot

uv sync --locked --all-groups
uv run --frozen ruff format --check .
uv run --frozen ruff check .
uv run --frozen pytest
uv run --frozen notes-bot --help
uv build
```

Return to the repository root:

```bash
cd ../..

git diff --cached --check
git status --short
```

### 4. Create the commit

Use a conventional commit describing the complete slice:

```bash
git commit \
  -m "feat(notes-bot): add Telegram bot foundation"
```

Confirm it:

```bash
git show --stat --oneline HEAD
git status --short
```

`git status --short` should produce no output.

### 5. Push the commit

```bash
git push origin main
```

No tag is needed. This is the beginning of the bot, not a completed bot release.

### 6. Watch GitHub Actions

If GitHub CLI is installed:

```bash
gh run watch
```

Otherwise, open the repository’s Actions page:

[notes-solution Actions](https://github.com/roman-kunitsyn/notes-solution/actions)

The CI workflow should include:

- Static checks
- Database migrations and tests
- Notes CLI
- Notes integration
- Notes bot

The new **Notes bot** job should perform formatting, linting, tests, entry-point verification, and package build.

Once the entire workflow is green, the foundation milestone is complete. Our next step will be authentication design documentation: the exact browser-based Telegram-to-Supabase linking flow, stored state, token lifecycle, threats, and trust boundaries—before we create any database migration or authentication code.
