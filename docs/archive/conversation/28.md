## First: audit the existing configuration

From `deploy/self-hosted`, run:

```zsh
git status --short

git ls-files \
  '.env' \
  '.env.*' \
  '*secret*' \
  '*backup*'

git check-ignore -v \
  .env \
  .env.production \
  ../../backups
```

The important expectation is:

```text
.env             ignored
.env.production  ignored
backups/         ignored
```

Check which official secret utilities are present:

```zsh
find utils \
  -maxdepth 1 \
  -type f \
  -print |
  sort
```

Inspect their supported interfaces:

```zsh
sh utils/generate-keys.sh --help 2>&1 || true
sh utils/add-new-auth-keys.sh --help 2>&1 || true
sh utils/rotate-new-api-keys.sh --help 2>&1 || true
```

Finally, list the environment variable names without exposing their values:

```zsh
sed -nE 's/^([A-Z][A-Z0-9_]*)=.*/\1/p' .env |
  sort
```

Do not run the key generators yet. Some official scripts modify `.env` directly, and we need to establish whether they support a separate production environment file before invoking them.

The goal is to maintain this separation:

| File                            | Purpose                        | Git       |
| ------------------------------- | ------------------------------ | --------- |
| `.env`                          | Current local deployment       | Ignored   |
| `.env.production.example`       | Documented placeholders        | Committed |
| `.env.production`               | Real future production secrets | Ignored   |
| `docker-compose.production.yml` | Linux/security overrides       | Committed |
| `docker-compose.colima.yml`     | macOS-only overrides           | Committed |

Your current deployment already uses Supabase’s new asymmetric authentication configuration (`JWT_KEYS`, `JWT_JWKS`, publishable and secret keys). Production will get a completely separate key set. Supabase requires the JWKS values to remain synchronized with the signing secret and authentication services, so we’ll use the provided generators rather than independently inventing JWT values. [Supabase self-hosted authentication keys](https://supabase.com/docs/guides/self-hosting/self-hosted-auth-keys).
