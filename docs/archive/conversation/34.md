The result is healthy:

- `401` from `/auth/v1/health` without an API key: Envoy correctly rejected the request.
- JWKS returned one public key.
- REST without an API key returned `401`.

My health-check script missed the required `apikey` header for Auth health. Let’s correct it.

## Fix `scripts/healthcheck.sh`

After `SUPABASE_URL`, load the publishable key without sourcing the environment file:

```sh
PUBLISHABLE_KEY="$(
  sed -n 's/^SUPABASE_PUBLISHABLE_KEY=//p' "$ENV_FILE"
)"

if [ -z "$PUBLISHABLE_KEY" ]; then
  echo "SUPABASE_PUBLISHABLE_KEY is missing" >&2
  exit 1
fi
```

Replace the Auth request with:

```sh
echo "Checking Auth..."

curl --fail --silent --show-error \
  "$SUPABASE_URL/auth/v1/health" \
  --header "apikey: $PUBLISHABLE_KEY" \
  >/dev/null
```

At the end, clear the extracted key:

```sh
unset PUBLISHABLE_KEY
```

Validate the script:

```zsh
sh -n scripts/healthcheck.sh
```

## Test the corrected request locally

Load the local publishable key:

```zsh
LOCAL_PUBLISHABLE_KEY="$(
  sed -n 's/^SUPABASE_PUBLISHABLE_KEY=//p' .env
)"
```

Test Auth:

```zsh
curl --fail --silent --show-error \
  http://127.0.0.1:8000/auth/v1/health \
  --header "apikey: $LOCAL_PUBLISHABLE_KEY" |
  jq
```

It should return the GoTrue health response.

Then:

```zsh
unset LOCAL_PUBLISHABLE_KEY
```
