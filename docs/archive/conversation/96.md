Yes, this is a resource leak revealed by the full suite.

The important detail is:

```python
with open_database(path) as connection:
```

A `sqlite3.Connection` context manager commits or rolls back the transaction, but it does **not close the connection**. The shorter runs pass, while the full suite accumulates open SQLite connections until macOS starts failing to open more database files.

## Fix the connection lifecycle

### 1. Add a managed connection helper

In `database.py`, add:

```python
from collections.abc import Iterator
from contextlib import contextmanager
```

After `open_database()`, add:

```python
@contextmanager
def database_connection(
    path: Path,
) -> Iterator[sqlite3.Connection]:
    connection = open_database(path)

    try:
        with connection:
            yield connection
    finally:
        connection.close()
```

This provides both behaviors:

- commit or rollback;
- guaranteed close.

Keep `open_database()` as the low-level function because transaction-sensitive operations use explicit `BEGIN IMMEDIATE`, `commit()`, `rollback()`, and `close()`.

## 2. Find leaking usages

From `apps/notes-bot`:

```bash
rg "with open_database" src tests
```

For every ordinary usage, replace:

```python
with open_database(path) as connection:
```

with:

```python
with database_connection(path) as connection:
```

Also update the imports in those files:

```python
from notes_bot.database import database_connection
```

If the file no longer calls `open_database()` directly, remove that import.

## 3. Do not change explicit transaction code

Keep this pattern unchanged:

```python
connection = open_database(database_path)

try:
    connection.execute("BEGIN IMMEDIATE")
    # ...
    connection.commit()
except Exception:
    connection.rollback()
    raise
finally:
    connection.close()
```

It is already correct.

This applies to functions such as:

- `consume_link_challenge()`
- `reserve_otp_request()`
- `record_failed_otp_attempt()`
- `complete_linked_session()`

## 4. Update tests too

Tests such as this:

```python
with open_database(path) as connection:
```

must also use:

```python
with database_connection(path) as connection:
```

Otherwise the test suite itself continues leaking connections.

After editing, run:

```bash
rg "with open_database" src tests
```

Expected result:

```text
no output
```

Direct assignments such as this are allowed and will not match:

```python
connection = open_database(path)
```

They must have a corresponding `connection.close()` in `finally`.
