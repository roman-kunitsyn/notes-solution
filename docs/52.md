The CLI’s functional MVP is complete. Next we should make it comfortable and reliable before starting the Telegram bot.

Recommended sequence:

1. Persistent CLI configuration
2. Editor-based note creation and editing
3. Friendly Supabase error messages
4. End-to-end CLI integration tests
5. Add the CLI to CI
6. Write installation and usage documentation
7. Begin `apps/notes-bot`

The immediate next step is persistent configuration:

```text
notes config set \
  --url http://127.0.0.1:8000 \
  --key sb_publishable_...

notes config show
notes config path
notes config clear
```

Then you won’t need to run:

```zsh
export SUPABASE_URL=...
export SUPABASE_PUBLISHABLE_KEY=...
```

Configuration precedence should be:

```text
environment variables
        ↓ override
local configuration file
```

The file can live next to the session:

```text
~/Library/Application Support/notes-cli/config.json
~/Library/Application Support/notes-cli/session.json
```

The publishable key is designed for client use; the CLI must still reject secret and service-role keys. Configuration should never accept:

```text
SUPABASE_SECRET_KEY
SERVICE_ROLE_KEY
sb_secret_...
```

After configuration, I recommend editor integration:

```zsh
notes create --editor
notes edit <note-id> --editor
```

It can open `$EDITOR`—Neovim in your case—with a simple title/content document. That will make the CLI genuinely pleasant rather than merely functional.
